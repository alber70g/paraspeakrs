# macOS dictation: text insertion, permissions, hotkeys and warm ASR in open-source apps

Date: 2026-11-04. Scope: how open-source macOS push-to-talk dictation apps put text into the
frontmost app and keep ASR latency low, as input for a `ctrl+\` dictation feature in the
paraspeakrs recorder (`packages/recorder-macos`).

Method: source code read from `raw.githubusercontent.com` (via Tavily extract, Exa crawl and
`curl`), repo trees via `gh api`. Line numbers are approximate and refer to `main`/`develop` on
2026-11-04. "Unverified" marks claims taken from READMEs, blogs or comments that were not
measured or reproduced here.

Related local research: `research/macparakeet-spokenly-long-audio-parakeet-chunking-strategy-research.md`
(long-audio chunking, not dictation).

### 2.2 Code that carries the decisions

VoiceInk Cmd+V (`CursorPaster.swift`):

```swift
let source = CGEventSource(stateID: .privateState)
cmdDown.flags = .maskCommand; vDown.flags = .maskCommand; vUp.flags = .maskCommand; cmdUp.flags = []
cmdDown.post(tap: .cghidEventTap); await wait(0.01)
vDown.post(tap: .cghidEventTap);   await wait(0.01)
vUp.post(tap: .cghidEventTap);     await wait(0.01)
cmdUp.post(tap: .cghidEventTap)
```

MacParakeet event posting (`AppGeneratedKeyboardEvents.swift`):

```swift
/// Inject application keyboard output downstream of the HID state table.
/// Posting at the HID entry point contaminates that table regardless of the
/// source state ID (#1286). Session posting still reaches the destination app.
static let postingLocation: CGEventTapLocation = .cgSessionEventTap
static func makeSource() -> CGEventSource? { CGEventSource(stateID: .combinedSessionState) }
```

FluidVoice gives the same reason: "Posting this pair at HID level used to leave Command held in
HID state; the session-level route avoids changing that physical-key state"
(`SystemPasteCommandPoster` in `TypingService.swift`/`PasteDeliveryCoordinator.swift`).

Handy receipt-based restore (`paste_tx/mod.rs`): the legacy fixed-delay restore "can lose the
race and the user gets their old clipboard pasted back (#502)". The macOS path publishes the
transcript as a promise with `declareTypes:owner:`; AppKit calls
`pasteboard:provideDataForType:` when a consumer reads it. Only reads after the chord count.
Constants: `QUIET_PERIOD = 200 ms`, `RESTORE_TIMEOUT = 8 s`, `FAILED_INJECTION_TIMEOUT = 500 ms`.

Epicenter ADR-0040: with Accessibility denied, the synthetic ⌘V "silently no-ops: the OS
delivers no event, but the synthetic-input call still reports success". The restore then wipes
the transcript. Decision: decide from the grant before the keystroke; if pasting is impossible,
leave the transcript on the clipboard.

### 2.3 Direct typing and Accessibility writes

| App | Typing via `CGEventKeyboardSetUnicodeString` | AX write |
| --- | --- | --- |
| VoiceInk | optional mode; 20 UTF-16 units per event, 10 ms between chunks, virtual key `0x31`, `.cghidEventTap`; LF sent as CR (Shift for line break), surrogate pairs never split | reads context only (`PasteTextContextReader`) |
| FluidVoice | default "direct" path; 200 UTF-16 units per chunk, 0 ms delay, `postToPid(targetPID)` first, then HID | approaches 0–3: `kAXSelectedTextRangeAttribute`+`kAXValueAttribute`, `kAXValueAttribute`, `kAXSelectedTextAttribute`, insertion point |
| Presspeech | optional; chunks split on grapheme limits; aborts if a physical modifier is held | AX messaging timeout 0.25 s for target checks |
| Hex | AppleScript `keystroke "<text>"` when clipboard paste is off | `kAXSelectedTextAttribute` on focused element as third paste fallback |
| MacParakeet | streaming cursor inserter exists (`StreamingCursorInserter.swift`, not read) | reads/replaces selection via `kAXSelectedTextAttribute` for transforms |

No project uses AX writes as the primary path. FluidVoice is the only one that tries direct
insertion first, and it falls back to the clipboard.

### 2.4 Fallbacks when no text field is focused

- FluidVoice: `DeliveryTargetAssessment.assessFocusedElement()`; if "certainly not editable", copy
  to clipboard and return `noEditableTarget`. Also `PasteVerifier` compares the AX value before and
  after to detect a paste that did not land.
- Epicenter: leave transcript on clipboard when the grant is missing ("emergency clipboard").
- Hex: if all three strategies fail, the transcript stays on the clipboard.
- MacParakeet: error string "Accessibility permission is required for auto-paste. Copied to
  clipboard. Press Cmd+V." (from the installed binary's strings).

### 2.5 Modifier state at paste time

Relevant for `ctrl+\` push-to-talk: the user may still hold Control when the transcript is ready.
Presspeech checks `CGEventSource.flagsState(.hidSystemState)` and refuses synthetic delivery while
Shift/Control/Option/Command/Fn is physically held ("A physically held modifier can turn our
Paste chord into a different app shortcut"). FluidVoice's post-insertion actions require
`modifiersReleased`. Handy holds Command 100 ms because some apps "poll global keyboard state".

## 3. Permissions

| Permission | Needed for | How apps check / prompt |
| --- | --- | --- |
| Microphone | recording | `AVCaptureDevice.authorizationStatus(for: .audio)` / `requestAccess` (MacParakeet `PermissionService.swift`, VoiceInk `OnboardingPermissionController.swift`) |
| Accessibility | posting synthetic key events into other apps; AX reads/writes; `.defaultTap` keyboard event taps | `AXIsProcessTrusted()`; prompt with `AXIsProcessTrustedWithOptions([kAXTrustedCheckOptionPrompt: true])` (MacParakeet, VoiceInk); Handy uses `tauri-plugin-macos-permissions` and polls until granted (`src/components/onboarding/usePermissions.ts`) |
| Input Monitoring | listen-only keyboard event taps | Hex checks `IOHIDCheckAccess(kIOHIDRequestTypeListenEvent)` and lets tap creation trigger the prompt; notes `IOHIDCheckAccess` returns stale denials (#250). OpenSuperWhisper tracks both grants and reconfigures triggers on change |
| none | Carbon `RegisterEventHotKey` chords | paraspeakrs `GlobalHotKey.swift` comment; Epicenter ADR-0019/0117 |

Observed facts and caveats:

- Installed MacParakeet 0.8.10 (`/Applications/MacParakeet.app`): `LSMinimumSystemVersion` 14.2,
  `LSUIElement` true, usage strings for microphone, system audio capture and calendars only.
  Entitlements: `device.audio-input`, `network.client`, `personal-information.calendars`; no
  `app-sandbox`. Accessibility has no Info.plist usage string; it is granted in System Settings.
- Sandbox status was checked only for MacParakeet (not sandboxed). The other apps' entitlements
  were not checked.
- Epicenter ADR-0117 (unverified here): "a stale post-update Accessibility grant reads as trusted
  through `AXIsProcessTrusted` yet silently drops the synthetic ⌘V". Their detection: a live
  `CGEventTap` that dies under a still-trusted grant. This matters for paraspeakrs because
  `paraspeakrs install-recorder` builds and signs the app locally; whether TCC keeps the grant
  across ad-hoc rebuilds is already listed as unverified in the recorder sidecar decision.
- `CGPreflightPostEventAccess()` / `CGRequestPostEventAccess()` (macOS 10.15+) check the
  event-posting grant specifically. None of the examined apps use them; whether they detect a
  stale grant is unverified.

## 4. Hotkeys

### 4.1 Detection mechanism and modes

| App | Mechanism | Modes | Hold-vs-tap threshold |
| --- | --- | --- | --- |
| VoiceInk | `CGEvent.tapCreate(.cgSessionEventTap, .headInsertEventTap, .defaultTap)` (`ShortcutEventTap.swift`) | toggle, push-to-talk, hybrid, double-tap | hybrid 0.5 s; double-tap 0.7 s; missed-release recovery (`recoverMissedRelease`) |
| Handy | `handy-keys` 0.3.4 (CGEventTap) default on macOS; Carbon via `tauri-plugin-global-shortcut` as fallback | Toggle, PushToTalk, HoldOrToggle (default) | `hold_threshold_ms` 300 |
| FluidVoice | CGEventTap `.cgSessionEventTap`, `.headInsertEventTap`, `.defaultTap`; skips its own synthesized events via `eventSourceUserData` | toggle, hold, automatic | 0.4 s (`automaticTapThresholdSeconds`) |
| MacParakeet | CGEventTap; `.listenOnly` for Fn trigger, `.defaultTap` otherwise | doubleTapAndHold (default), doubleTapOnly, holdOnly, singleTapToggle | 400 ms tap threshold, 100 ms startup debounce (`FnKeyStateMachine`) |
| Hex | CGEventTap `.cghidEventTap`, `.defaultTap`; re-enables taps macOS disabled silently after sleep (100 ms watchdog) | press-and-hold, double-tap lock | double-tap 0.3 s; minimum press 0.15–0.2 s, 0.3 s for modifier-only keys (`docs/hotkey-semantics.md`) |
| OpenSuperWhisper | `KeyboardShortcuts` (Carbon `RegisterEventHotKey` with `kEventHotKeyPressed` + `kEventHotKeyReleased`); separate monitors for modifier-only and mouse buttons | toggle, hold-to-record | 0.3 s (`holdThreshold`) |
| Epicenter | `tauri-plugin-global-shortcut` (Carbon on macOS) for all input (ADR-0117) | toggle; push-to-talk as chord hold via `Pressed`/`Released` edges | — |
| whisper-writer | pynput or evdev | continuous, voice_activity_detection, press_to_toggle, hold_to_record | `min_duration` 100 ms, `silence_duration` 900 ms |

All hybrid implementations start recording on key-down and decide at key-up: released before
the threshold → keep recording (toggle); released after → stop (push-to-talk). Example,
OpenSuperWhisper `ShortcutManager.swift`:

```swift
vm.startRecording()
if AppPreferences.shared.holdToRecord && session.isCapturing {
    let workItem = DispatchWorkItem { [weak self] in self?.holdMode = true }
    DispatchQueue.main.asyncAfter(deadline: .now() + holdThreshold, execute: workItem)   // 0.3 s
}
// key-up: if holdMode → stopRecording(); else recording continues until next press
```

### 4.2 Constraints that apply to `ctrl+\`

- Carbon `RegisterEventHotKey` delivers both edges when the handler is installed for
  `kEventHotKeyPressed` and `kEventHotKeyReleased` (sindresorhus/KeyboardShortcuts
  `Sources/KeyboardShortcuts/HotKey.swift` lines ~109–110, ~426–429). It needs no permission.
  The existing `GlobalHotKey.swift` in this repo installs only `kEventHotKeyPressed`.
- macOS 15 rejects `RegisterEventHotKey` registrations whose only modifiers are Option and/or
  Shift (error -9868; Apple Frameworks Engineer quoted at 5typos.net, eternalstorms.at,
  KeyboardShortcuts issue #176). Control is allowed.
- Secure Event Input (password fields, Terminal "Secure Keyboard Entry") stops CGEventTaps from
  receiving KeyDown/KeyUp; Carbon hotkeys keep working (Handy `src-tauri/src/secure_input.rs`
  header comment). Handy shadow-registers keyed bindings through Carbon while secure input is on.
- A Carbon hotkey consumes the chord system-wide. `ctrl+\` is SIGQUIT (`^\`) in terminals; while
  registered, terminals will not receive it.
- `kVK_ANSI_Backslash` (0x2A) is a physical key position. On non-ANSI layouts the key that types
  `\` can differ (not checked).
- Escape to cancel: register it only while recording, otherwise it is swallowed globally.
  OpenSuperWhisper registers `.escape` and keeps it disabled; Handy shadows the cancel binding
  dynamically while recording.
- Key auto-repeat on a held Carbon hotkey: behaviour not verified here. Treat a second
  "pressed" without an intervening "released" as a repeat and ignore it.

## 7. Recommendation for paraspeakrs `ctrl+\` dictation

Assumption to confirm: the feature lives in the existing Swift recorder app
(`packages/recorder-macos`, macOS 15+), not in the Python CLI.

1. **Insertion.** Clipboard + synthetic Cmd+V, as every examined app does by default.
   - Snapshot every pasteboard item and type (MacParakeet/VoiceInk pattern).
   - Write the transcript as `.string` plus `org.nspasteboard.TransientType`,
     `org.nspasteboard.ConcealedType`, `org.nspasteboard.AutoGeneratedType`; record `changeCount`.
   - Before posting, wait until no physical modifier is held
     (`CGEventSource.flagsState(.hidSystemState)`), with a timeout of about 1 s; on timeout,
     leave the text on the clipboard.
   - Post V↓/V↑ with `.maskCommand` from `CGEventSource(stateID: .combinedSessionState)` at
     `.cgSessionEventTap`; keycode resolved with `UCKeyTranslate` under the Command modifier,
     fallback `kVK_ANSI_V`; mark events via `eventSourceUserData`.
   - Restore after 500 ms only if `changeCount` is unchanged. If Electron/browser targets paste
     the old clipboard, switch to Handy's promise-receipt restore (`declareTypes:owner:`,
     200 ms quiet period, 8 s cap).
   - If `AXIsProcessTrusted()` is false or the post fails, do not restore; keep the transcript on
     the clipboard and notify.
2. **Permissions.** Microphone via `AVCaptureDevice.requestAccess`. Accessibility via
   `AXIsProcessTrustedWithOptions` with the prompt, triggered from a menu item or first use, then
   poll `AXIsProcessTrusted()` every ~1 s until granted. No Input Monitoring if the hotkey uses
   Carbon. Open question: whether the grant survives `install-recorder` rebuilds (Epicenter
   reports stale grants that read as trusted).
3. **Hotkey.** Carbon `RegisterEventHotKey(kVK_ANSI_Backslash, controlKey)` with handlers for
   pressed and released. Start recording on press. Released before 300–400 ms → toggle (the next
   press stops); released later → push-to-talk stop. Register Escape only while recording.
   Ignore repeated "pressed" events. Accept that terminals lose `^\`.
4. **Warm ASR.** FluidAudio Parakeet TDT v3 in-process: load `AsrModels` and an `AsrManager` at
   app launch and after wake (VoiceInk pattern), keep them resident, prepare the AVAudioEngine
   graph while idle (Presspeech pattern). Reuses the 461 MB model MacParakeet already downloaded
   to `~/Library/Application Support/FluidAudio/Models`. Alternative: a resident sherpa-onnx
   daemon reuses the existing Python stack, at an unmeasured but likely GB-range idle RSS.
   Measure resident RSS and press-to-paste latency for both before choosing.

Questions to answer before implementation:

1. Does dictation go into the Swift recorder app (yes/no)?
2. Is a new Apache-2.0 dependency (FluidAudio) acceptable in the recorder (yes/no)?
3. Default mode: hybrid hold-or-toggle, or push-to-talk only?
4. Keep the transcript on the clipboard after pasting (yes/no)?
