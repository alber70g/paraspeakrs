# Agent CLI: file-based speaker naming

A command-line flow a coding agent can drive end to end, separate from the MCP
server and without the `mcp` extra. The user names speakers by renaming files.

## Commands

```
paraspeakrs agent transcribe <audio> -o <out_dir>   # step 1
paraspeakrs agent apply <out_dir> [--dry-run]       # step 2, repeatable
paraspeakrs agent help                              # prints the agent guide
```

Both print JSON on stdout; progress and errors go to stderr (exit 2 on an
expected failure, like the rest of the CLI).

## Output directory

```
out/
  transcript.txt              # regenerated by every apply
  manifest.json               # job_id + per-speaker suggestion; apply's input
  NEXT_STEPS.md               # instructions for the user and the agent
  SPEAKER_00__NAME-ME.wav     # nobody known
  SPEAKER_01__Alice_0.63.wav  # voice-library suggestion with its score
  SPEAKER_02__Bob.wav         # already named on this job (reused job)
```

The job itself stays in the shared store (`mcp-jobs`), so the TUI and MCP
server see the same names. `manifest.json` only records which job and what was
suggested, which is what makes apply idempotent.

## Samples: montages

Each sample stitches up to three of the speaker's longest segments of at least
1.5 s (each capped at 10 s), in time order, with a short beep between them.
While that is under 8 s, the next-longest segments are added whatever their
length, until 8 s or the speaker's audio runs out. No follow-up "more samples"
command.

## What a rename means

| File state on apply | Result |
|---|---|
| `SPEAKER_00__NAME-ME.wav` | unnamed, keeps `SPEAKER_00` |
| `SPEAKER_01__Alice_0.63.wav` untouched | named Alice, **not** taught to the voice library |
| `SPEAKER_01__Alice.wav` / `__Carol.wav` | named, taught to the voice library |
| two files with the same name | both speakers get it (merge) |
| file deleted | speaker's lines dropped from the transcript |
| unrecognised `.wav`, duplicate id, empty name | error, nothing changed |

A suffix only counts as a suggestion when it exactly equals the manifest's
suggestion (`<name>_<score>`), so a real name like `Room_2` is never misread.

Apply sets the full state each run: a changed name unfolds the old voice, a
restored file un-drops the speaker, so renaming again and re-applying works.

## Text hints

The transcribe JSON and NEXT_STEPS.md list each speaker's first three lines
with timestamps, so the agent can suggest names from context.

## Code

- `snippets.py`: `montage_segments()` (selection) and `write_montage()` (stitching).
- `labeling.py`: `speaker_montages()` (one source rebuild for all speakers) and
  `set_speaker_excluded()` (idempotent, unlike the toggle).
- `agent_dir.py`: prepare / plan / apply over the directory.
- `agent_guide.md`: packaged guide printed by `agent help`.
- `cli.py`: the `agent` subcommand.

## Verification

1. Montage selection: 3 / fewer / none-long-enough fallback → unit tests.
2. Filename parsing and every row of the table above → tests against a fake pipeline.
3. Idempotency: apply twice, rename + apply, restore a deleted file → tests.
4. Voice library: suggestion not taught, confirmed name taught, rename unfolds → tests.
5. Full suite green; one real run on an actual recording with ffmpeg.
