# Plan: Nemotron 3.5 Transcribe as an ASR backend (and optional speaker source)

Status: approved 2026-10-29 (clean transcript style; losing cross-recording names in speaker mode accepted). Research: `research/nemotron-3.5-transcribe-30b-serving-memory-and-speaker-chunking.md`.

## Decisions taken with the user (2026-10-29)

- Model: Nemotron 3.5 Transcribe 30B-A4B (not the 0.6B streaming model).
- Runs on a 24 GB NVIDIA GPU box and on an Apple-Silicon Mac → served by a local HTTP server.
  The client supports both **vLLM** and **NeMo-Speech.cpp** (`nemo-speech serve`).
- Nemotron's own speaker tags are an **optional** replacement for speakrs/senko diarization.
- Request length follows what the hardware can hold (a setting), not a fixed 90 s chunk.

## Changes

1. **`src/paraspeakrs/nemotron.py`** (new): `NemotronTranscribeAsr`, implementing `AsrEngine`.
   - `server: "nemo-speech" | "vllm"`, `base_url`, `model`, `speakers: bool`, `context_terms`,
     `timeout`.
   - POSTs the WAV chunk as base64 to `/v1/chat/completions` with the card's prompt
     (clean style: punctuation + capitalization, fillers and accidental repetitions omitted; speaker-tag prompt when `speakers`; `Context terms:` when set).
   - Parses words from vLLM `ctc_timestamps.words` or NeMo-Speech.cpp `transcription.words` into
     `Word(word, start, end, speaker)`; falls back to text-only when timestamps are missing.
   - httpx (already a dependency); no new packages.
2. **Config / CLI** (`config.py`, `cli.py`):
   - `AsrBackend` gains `"nemotron"`; `--asr-backend nemotron`.
   - Settings + env: `PARAKEET_NEMOTRON_SERVER` (default `nemo-speech`), `PARAKEET_NEMOTRON_BASE_URL`
     (default `http://127.0.0.1:8080`), `PARAKEET_NEMOTRON_MODEL`, `PARAKEET_NEMOTRON_MAX_REQUEST_SECONDS`
     (default 1500 = 25 min, under NVIDIA's validated 29 min for 24 GB; 3600 on 32 GB+ / 64 GB Mac),
     `PARAKEET_NEMOTRON_CONTEXT_TERMS`. Matching `--nemotron-*` flags.
3. **Factory** (`factory.py`): build the engine; `describe_asr` branch; when the backend is
   `nemotron`, the chunk target becomes `nemotron_max_request_seconds` (fewer, longer requests;
   the existing word-timestamp overlap dedupe keeps working).
4. **Optional speaker mode**: `DiarBackend` gains `"nemotron"` (`--diar-backend nemotron`, only valid
   with `--asr-backend nemotron`).
   - Pipeline branch: skip the diarizer; fixed chunks of `max_request_seconds` with 60 s overlap;
     ask for speaker tags.
   - Speaker tags are per request, so chunk N+1's tags are mapped onto chunk N's by majority vote
     over the words both chunks transcribed in the overlap (FluidAudio keeps identities consistent with
     whole-file clustering; with tags already present, overlap voting is the cheap equivalent).
     Unmatched tags get new speaker IDs.
   - Build `DiarizationSegment`s from runs of same-speaker words, IDs in the existing
     `SPEAKER_00` format, so labeling, samples, montages and `talk_seconds` keep working.
   - Skip `merge_asr_with_diarization`'s speaker overwrite for this mode.
   - `validate_runtime` no longer requires the speakrs binary in this mode.
5. **Tests** (no model needed): request building per server, response parsing for both shapes
   (fixtures from the documented formats), overlap tag mapping, ASR-derived diarization segments,
   config/CLI validation.
6. **Docs**: README (backend section + server setup for both machines), CHANGELOG `[Unreleased]`,
   `agent_guide.md` if it lists backends, `WORKLOG.md` (new, referenced from `AGENTS.md`).

## Known limits

- **No cross-recording speaker recognition in Nemotron speaker mode.** Speaker profiles depend on
  speakrs/senko voice fingerprints; Nemotron returns none. Naming still works per recording, but
  nothing is learned for the next one. (Alternative: also run speakrs embeddings on Nemotron's turns;
  more work, and the speakrs sidecar is macOS-only.)
- Dutch speaker tagging is not an advertised capability of the model.
- Nothing can be run against the real model in this sandbox (no GPU); verification is unit tests with
  documented response shapes. NeMo-Speech.cpp field names come from its `docs/api.md`.

## Success criteria

- `uv run pytest -q` passes, including the new tests.
- `paraspeakrs run --asr-backend nemotron ...` builds a pipeline and sends the documented request
  (checked with a mock server in tests).
- Manual check left to the user: one real run per server type.
